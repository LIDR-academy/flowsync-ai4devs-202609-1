## What this repo is

FlowSync is a **course exercise starter repo** (LIDR AI4Devs), not a finished product. The README frames the actual task on this branch (`s1/start`) as: duplicate the project, set up an "AI harness" (CLAUDE.md, Jira MCP, custom skills, a review subagent, a formatting hook) on only one copy, then run the same ticket through both copies and compare the agent's output. See `README.md` for the full exercise brief and delivery format (`docs/harness/comparacion.md` + `prompts.md`), and `prompts.md` for the running log of prompts used.

The intended end product is a team task-management app: an AdonisJS API (`backend/`) + a React SPA (`frontend/`). Right now only auth (signup/login/logout/profile) exists — no task/board features yet. The frontend is still the unmodified Vite React template (no API calls wired in).

There is **no root `package.json`** — `backend/` and `frontend/` are two independent npm projects, normally run in two separate terminals.

## Commands

### Backend (`backend/`)

```bash
npm install
cp .env.example .env
node ace generate:key      # writes APP_KEY into .env
node ace migration:run     # also regenerates database/schema.ts / schema_rules.ts
npm run dev                # ace serve --hmr, http://localhost:3333
npm run build               # ace build
npm run test                 # ace test (runs both Japa suites: unit + functional)
npm run lint                  # eslint .
npm run format                 # prettier --write .
npm run typecheck                # tsc --noEmit
```

Run a single suite with `node ace test unit` or `node ace test functional` (suite names come from `adonisrc.ts`).

**Node version requirement:** this project needs **Node >= 24**. It relies on `@poppinss/ts-exec` (invoked from `ace.js`) to run TypeScript natively — there's no ts-node/tsx. On Node < 24 every `node ace ...` command fails with `ERR_UNKNOWN_FILE_EXTENSION` on `bin/console.ts`. Check `node --version` before assuming an `ace` command is broken for another reason.

### Frontend (`frontend/`)

```bash
npm install
npm run dev       # vite, http://localhost:5173
npm run build     # tsc -b && vite build
npm run lint      # oxlint
npm run preview
```

## Backend architecture (AdonisJS 7)

- **Subpath imports, not relative paths.** `package.json` `imports` maps `#controllers/*`, `#models/*`, `#validators/*`, `#transformers/*`, `#middleware/*`, `#database/*`, `#providers/*`, `#generated/*`, etc. Always import via these aliases (e.g. `import User from '#models/user'`), matching the existing code — this is how AdonisJS's module system and IoC resolve things, plain relative imports across app/ boundaries are not the convention here.

- **Generated files — don't hand-edit:**
  - `database/schema.ts` and `database/schema_rules.ts` are regenerated by `node ace migration:run` from the migrations in `database/migrations/`. Models compose from these `*Schema` base classes (e.g. `User extends compose(UserSchema, withAuthFinder(hash))` in `app/models/user.ts`) rather than declaring columns directly.
  - `.adonisjs/` (client registry, generated controllers/routes types) is produced by Tuyau (`@tuyau/core`) and Adonis hooks declared in `adonisrc.ts` (`indexEntities`, `generateRegistry`). `start/routes.ts` references controllers through the generated `controllers` object (`import { controllers } from '#generated/controllers'`), not by string path — e.g. `router.post('signup', [controllers.NewAccount, 'store'])`.

- **Dual auth guards** (`config/auth.ts`): `api` guard (token-based, `tokensGuard`) is the default, used for the JSON API; `web` guard (session-based) also exists. `AccessTokensController` issues/revokes tokens; `NewAccountController` signs up + issues a token; `ProfileController` reads the authenticated user. Route groups under `/api/v1` mount `auth/*` (signup, login — public) and `account/*` (profile, logout — behind `middleware.auth()`), see `start/routes.ts`.

- **Global middleware pipeline** (`start/kernel.ts`): server-level middleware (force-JSON responses, CORS) runs on every request; router-level middleware (bodyparser, session, shield, auth initialization, `SilentAuthMiddleware`) runs on routed requests. `SilentAuthMiddleware` calls `auth.check()` on every request so `auth.user`/`auth.isAuthenticated` are available without forcing a 401; the named `auth` middleware (`AuthMiddleware`, applied per-route) is what actually rejects unauthenticated requests.

- **Response shape:** controllers return via `ctx.serialize(...)` (added to `HttpContext` by `providers/api_provider.ts`), which wraps every response in `{ data: ... }` and handles Lucid pagination metadata consistently. Use `serialize.withoutWrapping(...)` when a raw (unwrapped) body is needed. Transformers (e.g. `UserTransformer extends BaseTransformer<User>`, using `this.pick(...)`) control which model fields get serialized — don't return raw Lucid model instances from controllers.

- **Validation** is done with VineJS validators in `app/validators/` (e.g. `signupValidator`, `loginValidator` in `app/validators/user.ts`), invoked via `request.validateUsing(...)` inside controllers.

- Database is SQLite (`better-sqlite3`), configured in `config/database.ts`. When passwords or other sensitive data is stored, the md5 hash will be stored instead.

## Frontend

Plain Vite + React 19 + TypeScript template (no router, no state library, no API client wired up yet). `oxlint` is the linter (`frontend/.oxlintrc.json`); type-aware lint rules are not enabled by default (see `frontend/README.md` for how to turn them on).

## Reglas de proceso

commitear directo en `main`/`s1/start`.

completa de los cambios en el cuerpo del PR.

darlo por terminado.
- No repitas ese resumen en el chat: la sesión se va a perder, el PR no. Responde solo
con la URL del PR.
